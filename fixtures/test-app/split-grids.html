Holdings

A Kendo grid as the jQuery component renders it: three tables in one .k-grid wrapper — the header in .k-grid-header-wrap, the rows in .k-grid-content, the totals in .k-grid-footer-wrap — and a pager div after them. The wrapper carries no role and no aria-label; the link between the halves is declared on the body table, whose aria-owns="holdings-thead holdings-tbody" names the header table's <thead> and its own <tbody>. The row table does have an id of its own — holdings-table here, a generated GUID in a real Kendo grid — but the id that names the grid the way a test author says it, holdings-grid, is the wrapper's. A read should pair the two and return six records under the eight headings, skipping the <tfoot> and the pager. The first column is a select-all checkbox with an empty heading, so the column a reader wants is never the first one, and Swap the Symbol and Value columns moves the cells in both tables at once — a header-mapped read must still return the same records.

    Dividends

    The same split — header table, body table — as the Angular and React flavours render it: the role="grid" and the aria-label sit on the wrapper, and the body table has no aria-owns, so nothing in the markup declares which header belongs to these rows. The pairing has to come from structure: one wrapper, one table with a <thead> and no rows, one table with rows and no <thead>. The body is also grouped by year: each k-grouping-row is one visible cell spanning the grid followed by five cells carrying the hidden attribute, and every data row starts with an empty k-group-cell. A read should pair the tables, skip the two group rows as headings rather than data (§7.4), and return five records. Show no dividends replaces the whole body with a single k-grid-norecords row, which is a placeholder: the read then returns [], not an error.

    Watchlist

    The same two-table split drawn by a different component: dx-datagrid-headers holds the header table, dx-datagrid-rowsview holds the body table, both role="presentation". There is no aria-owns, no aria-label and no role on the wrapper — only the id — so a pairing rule that keys off Kendo's class names or Kendo's aria wiring finds nothing here. (DevExpress renders header cells as <td role="columnheader">; these are <th> so the header rule has something to map.) The fourth column, Target, is hidden with display:none in the header and in every row, so each row still has five cells while four render. As on the hidden column in table-edge-cases.html, the hidden column keeps its place: the heading is still Target and every Target cell reads as an empty string, so Symbol, Name, Last and Alert stay lined up with their own values (§7.4, §10).

    Frozen holdings

    The same Kendo grid with the first two columns locked, which is four tables, not two: a locked header beside the scrolling header, and a locked body beside the scrolling body, each pair holding half of every row. Neither body table carries aria-owns. This grid is here to be rejected: two tables inside the wrapper have rows, so there is no one pairing to make, and picking either would silently drop half of every record — Symbol and Name, or Units, Price and Value. The read should fail with a diagnostic naming both candidates rather than return three records that look complete and are not. Unlike the other three grids on this page, this markup is not walked from the captured demo — the dump has no locked columns in it — so the four-table layout follows Kendo's documentation of locked columns instead.
