How a read sees a table

A column is named either by the text of its header or by its position, so a table with no header row is still readable — you just count the columns yourself. Every record the read stores carries _row, the row's one-based position among the data rows, which is how a later step points at the right row when two rows look alike. Rows that are hidden on the page are not data, and neither is anything in the <tfoot>, so a total under the table never turns up as a row; read it separately. A body whose only content is one cell spanning the whole table — “No documents uploaded yet.”, “Loading…” — is an empty table, and the read stores an empty list rather than failing. Anything else that merges cells with rowspan or colspan is refused outright, because a guessed grid looks right and is wrong. And a loop never holds on to a row it read earlier: each pass finds its row again by a value, such as an order ID, or by _row.
