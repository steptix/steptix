Loan applications

A RadGrid with static headers, as the live Telerik demo renders it: three tables in one .RadGrid wrapper — the header in .rgHeaderWrapper > .rgHeaderDiv, the rows in .rgDataDiv, and the pager in a third table that is a direct child of the wrapper. The header table's <thead> has three rows: a band row of merged groups (Applicant, Loan, Review), a leaf row of the eight column names, and a rgFilterRow of nine <td> that is not a header row at all. Its <tbody> holds a hidden spacer row of one <td colspan="9">. The data table brings a <thead> of its own — one hidden, empty <th> — so the nearest header says nothing; the real one is named by aria-owns="RadGrid1_ctl00_Header_thead RadGrid1_ctl00_tbody " on the data table (trailing space included, as RadGrid emits it). Row ids are zero-based and are renumbered from __0 on every page, so RadGrid1_ctl00__3 is a position, never a record. Two applicants on this page are both called Sarah Mitchell, so a step that names an applicant is ambiguous and _row is what tells them apart. A read of Applicant, Amount and Status by heading should return the 10 records on page 1 — not the spacer, not the filter row, not the pager, and not a detail row if one is open. Watch two things: the header CSS upper-cases every heading, so innerText says APPLICANT where the markup says Applicant; and the expand column's <th> renders blank but its textContent is ExpandColumn, hidden in a display:none span.

Direct debit mandates

The same component with ClientSettings.Scrolling.AllowScroll="false", which is the form documentation describes and the live demo does not show: there is no header wrapper and no separate pager table, so one table carries everything. The band row, the leaf row and the filter row are all in the <thead>, the eight mandates are in the <tbody>, and the pager is a rgPager row in the <tfoot> spanning all seven columns. Because RadGrid emits aria-owns either way, here it points at this table's own <thead> and <tbody> — a self-reference that must not be read as a pairing with some other table. Row ids are zero-based again. A read by heading should return the 8 mandates, skipping the filter row and the pager.

Quarterly fees

The same banded header with no component around it: one <table>, two header rows, four body rows. Account spans both header rows; Q1 and Q2 each span two columns and are not columns themselves — nothing in the body lines up under them. The leaf names repeat: two columns are called Fee and two are called Rebate, so a read of "Fee" is ambiguous and has to be told which by position — or the band and the leaf have to be read together, which the runtime spells Q1 > Fee and Q2 > Fee — plain Q1 Fee is refused. The header grid is five columns wide, not seven.
